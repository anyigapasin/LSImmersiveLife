## 4. User’s Core Design Intent

The user does not want one giant system that automatically assumes every mode is Police.

The main menu is intended to select the roleplay identity. It should not contain all Police, Gang, Citizen, Dispatch, NPC, or Crime Activity logic directly.

The intended relationship is:

```text
LS Immersive Life Main UI
        ↓
Roleplay selection
        ↓
Authority routing
        ↓
Police Authority UI
        ↓
Police Core coordinator
        ↓
Police Authority/Profile/Session state
        ↓
Specialized Police systems
        ↓
XML/profile/data collections
```

Police Core is the coordinator and processor for the Police Authority session. It is not supposed to own every gameplay behavior itself.

Specialized systems should retain ownership of their own logic:

- Dispatch owns universal urgent Dispatch events.
- Crime Activity owns the quiet group-crime intelligence catalog.
- NPC Response owns foot and traffic interaction behavior.
- Convoy owns custody and transport movement.
- Police Response owns backup/response units.
- Gang Data Integration reads external gang data.
- Audio Dispatch owns audio loading, scheduling, and playback.
- Police Profile owns catalog parsing, selection, favorites, and persistence.
- LSPDAuthority owns Police Authority session state and authority-level settings.
- Police UI presents the state and invokes the appropriate owner through Police Core.

The user explicitly rejected duplicating specialized systems inside `PoliceCore`.

## 5. Police Authority Activation Boundary

### Required behavior

GTA V must launch normally.

At game launch:

- Police Authority is OFF.
- The player remains a normal GTA protagonist.
- No saved Police profile is applied.
- No Police audio session is active.
- No Police patrol is active.
- No Dispatch producer is armed.
- No Police station markers are applied.
- No Police world behavior controls are applied.
- No player model, vehicle, weapon, wanted state, or relationship state is changed.

The player must open the universal LS Immersive Life menu and deliberately choose:

```text
Police Authority
```

Only then does the Police Authority session start.

The old bug was that Police Duty or Police behavior became active immediately after GTA launch, before the player selected Police mode. This was explicitly rejected.

### Current implementation

The current implementation uses:

```text
LSRoleplay.cs
LSAuthorityRole.cs
LSImmersivePoliceUI.cs
LSImmersivePoliceCore.cs
LSPDAuthority.cs
```

The current role enum includes:

```text
NoneSelected
Citizen
PoliceAuthority
GangLeader
```

The current `LSAuthorityRole` behavior:

- Records the selected roleplay mode.
- Keeps Police, Citizen, and Gang menus separate.
- Routes the Police Authority role into `LSImmersivePoliceUI`.
- Does not activate the Police session merely because the role is selected.
- Waits for the Police Authority UI to be explicitly opened before the Police core is activated.
- Logs `ROLEPLAY_MODE_SELECTED`.

Citizen and Gang Authority routes are currently not connected to equivalent gameplay UI in this focused Police implementation. They log unavailable authority routing rather than showing misleading placeholder controls.

The latest runtime log confirms that Police Authority is selected after the universal UI boots, not automatically at initial GTA startup.

### 6.2 Previous runtime problems

Historical gameplay and production logs repeatedly recorded these problems:

- Police Duty activated automatically when GTA launched.
- Police UI and Main UI boundaries were unclear.
- Dispatch and Chaos Activity could overlap.
- A player could be physically inside a Chaos scene but the interaction routed into Dispatch.
- Multiple PolIgnus patrol vehicles could be spawned because existing patrol vehicles were not consistently reused or retired.
- Selecting a station could teleport the player and vehicle into unsafe or unverified locations.
- The player and vehicle could fall through the world when station patrol was selected.
- Dispatch entities could disappear instantly when a suspect was defeated.
- Dead suspects could disappear instead of remaining as visible aftermath.
- Arrested suspects could disappear instantly during transport.
- Prisoner and transport vehicle could disappear immediately on prison arrival.
- Transport could visually finish while internal Convoy/Dispatch state remained active.
- The player needed manual reset or a terminal transport-completion action when a state became stuck.
- “Driver fled” could appear even though the vehicle was still stationary.
- NPC crowds could run as though a zombie event had begun.
- Vehicles could ram the Police player during Police activity.
- NPCs could continue treating the Police player as a normal civilian.
- Vanilla Police could aim at or attack the player even after Police Authority was selected.
- Foot NPC interaction was stiff and failed to hold the citizen in place.
- Traffic interaction was incomplete and drivers could leave or fail to behave physically.
- Criminal groups sometimes stood still rather than performing activity-specific actions.
- Gang suspects could receive inappropriate heavy weapons.
- Crime Activity, Gang activity, Chaos activity, and Dispatch activity could happen simultaneously.
- Dispatch audio could be delayed because active incident maintenance was throttled together with new activity discovery.
- Source packages contained mixed revisions that produced large compile-error cascades.
- A newer Dispatch file could expect fields absent from the older `AnyiLSPDEvents.cs`.
- A newer Convoy file could expect profile fields that did not exist in the older profile.
- `List<>` imports and configuration fields were missing when isolated files were copied between revisions.
- The resulting mixed-revision build reached approximately 35 errors in one historical state.
- The old project sometimes produced packages that were full merged snapshots even when the user asked for only Police Authority files.

### 6.3 Current architecture was created to address these problems

The current `LSImmersiveLife` project was intended to provide:

- explicit Authority gating
- one current source architecture
- one current profile system
- XML-driven collections
- separate Police UI and Police Core
- separate Dispatch, NPC, Crime Activity, Convoy, Response, Audio, and Gang data owners
- event-based runtime logging
- separate debug logging
- no Chaos Response dependency
- no automatic Police activation
- deferred cleanup of owned entities
- no global “ignored by everyone” behavior
- local traffic awareness instead of global traffic suppression
- read-only external Gang data
- safe exterior station coordinates unless interiors are verified
- personal favorites separated from generic Police catalogs

### Enter sequence

The intended activation sequence is:

1. Check whether Police Authority is already active.
2. Capture normal player state.
3. Enter `LSPDAuthority`.
4. Activate Police audio session.
5. Reload optional Gang data.
6. Load saved Police profile and personal weapons.
7. Log profile and Authority activation.
8. Apply saved profile where possible.
9. Activate station markers.
10. Return a status message.

### Exit sequence

The intended deactivation sequence is:

1. Stop Police audio.
2. Reset Patrol.
3. Reset Dispatch.
4. Reset Convoy.
5. Reset Police Response.
6. Remove station markers.
7. Reset Gang integration state.
8. Reset NPC interaction.
9. Exit `LSPDAuthority`.
10. Release the owned Police vehicle.
11. Restore normal player state.
12. Log `POLICE_AUTHORITY_DEACTIVATED`.

### Current processing order

When Police Authority is active, `LSImmersivePoliceCore.Process`:

1. Processes `LSPDAuthority`.
2. Processes Dispatch.
3. Updates Police Response if a Dispatch incident exists.
4. Releases response units when no active incident exists.
5. Processes Convoy.
6. Mirrors Convoy transport states into Dispatch without taking Convoy ownership.
7. Completes or cancels Dispatch when Convoy reaches terminal states.
8. Processes NPC Response.
9. Processes Audio.

This is intended to preserve subsystem ownership, but timing/arbitration between Dispatch and NPC interaction remains an area to review.

## 18. `LSPDNPCResponse.cs`

It must remain separate from Gang behavior and Dispatch.

The user does not want:

```text

Make every civilian run
Stop all traffic
Disable all NPC behavior
Rewrite Gang Data
```

The intended behavior is local and contextual.

### Foot interaction

Desired behavior:

1. Player approaches an ordinary or suspicious pedestrian while on Police patrol.
2. The pedestrian notices the Police player.
3. The pedestrian slows or stops.
4. The pedestrian faces the officer.
5. The player initiates interaction.
6. The citizen can prepare documents using a simple hand/head gesture.
7. The citizen can comply, remain, argue, refuse, or flee.
8. The player can release, lecture, escalate, or pursue.
9. The citizen should not walk away while the interaction is actively taking place.
10. Gang and MemberPool gang data remain outside this ordinary civilian layer.

```text
FootDocuments
FootRefused
TrafficPreparing
```

Other current logic includes holding the subject, releasing the subject, clearing interaction state, and recently released vehicle memory.

6. Driver presents documents or responds.
7. Player agrees/releases, rejects/escalates, or the driver flees.
8. If the driver flees, the vehicle must physically drive away.
9. The player can pursue until the vehicle stops, crashes, or the driver is otherwise resolved.
10. The driver should not immediately disappear from the vehicle.
11. The system must work whether the officer begins on foot or in a Police vehicle.

## One important adjustment to the MainConfig idea

Your goal is right: one understandable place for editable settings. But it should not work by “automatically scanning every C# file and guessing which variables are configuration.”

That would become dangerous and confusing because the game cannot reliably know whether a value is:

- a safe editable setting;
- a temporary runtime state;
- an internal timer;
- an entity handle;
- a gameplay constant that should not be exposed;
- content data such as a ped model, station, weapon, crime definition, or gang entry.

The maintainable version of your design is:

```text
Each system explicitly declares the settings it allows the player to edit
→ LSImmersiveMainConfig registers and validates those settings
→ LSImmersiveMainUI.xml stores them in clear named sections
→ LSMainSetting / LSImmersiveHotkeys display and edit them
→ the owning system reads its typed section
```

So a Dispatch system could explicitly declare:

```text
Dispatch.Enabled
Dispatch.QuietPatrolMinimumSeconds
Dispatch.QuietPatrolMaximumSeconds
Dispatch.GlobalCooldownSeconds
Dispatch.RepeatProtectionMinutes
Dispatch.MaximumActiveIncidents
Dispatch.SceneSpawnDistance
Dispatch.AudioEnabled
Dispatch.AudioMinimumGapSeconds
```

The NPC system could explicitly declare:

```text
NpcResponse.Enabled
NpcResponse.InteractionRadius
NpcResponse.TrafficStopRadius
NpcResponse.LocalTrafficAwarenessRadius
NpcResponse.CollisionGuardCooldownSeconds
NpcResponse.MaximumTrafficVehiclesAffected
NpcResponse.CitizenReactionEnabled
NpcResponse.VehicleStopTimeoutSeconds
```

The Convoy system could explicitly declare:

```text
Convoy.Enabled
Convoy.TransportVehicleModel
Convoy.StationArrivalRadius
Convoy.PrisonArrivalRadius
Convoy.PrisonerRecoveryTimeoutSeconds
Convoy.AllowTerminalCompletion
```

The systems still own the meaning and validation of those values. `LSImmersiveMainConfig` owns the single XML file, loading, saving, preserving sections, and presenting a clean overview.

That prevents every gameplay file from generating its own random `.ini` or XML file while also preventing one massive C# configuration class with hundreds of unrelated hard-coded fields.

- whether the ped still existed;
- whether the ped was dead;
- whether the ped was in the intended vehicle;

There is also a practical performance concern: the current logger writes synchronously to disk. The recent log showed repeated `NPC_TRAFFIC_COLLISION_GUARD` entries roughly every fraction of a second. That does not prove it caused the freeze, but high-frequency file writing on the game thread is avoidable pressure. The separation from Dispatch is enforced in the Core:

- Crime Activity discovery only runs during a quiet Police Patrol.
- A Crime Activity **tip** is passive intelligence. It does not create a Dispatch offer, GPS route, criminal scene, Backup request, or urgent incident by itself.
- An actual Crime Activity starts only after the player chooses **Begin Current Investigation** near the selected location.
- While a Crime Activity scene is active, Dispatch, Convoy, Gang incidents, NPC interaction, and new Backup assignments are prevented from overlapping it.
- If a Dispatch, Convoy, Gang incident, NPC interaction, or Backup assignment becomes active while a passive Crime tip exists, the tip remains available in the UI but stays silent. It will not post a notification or play audio over the other activity.
- Closing, ignoring, abandoning, or resolving Crime Activity defers new Dispatch offers for a short context-clear period.

The new real scene behavior includes:

- One owned Crime Activity scene at a time.
- Asynchronous model preparation with a configurable timeout; there is no `Script.Wait` inside menu callbacks.
- Configurable **2–6** owned criminal participants and an optional authored scene vehicle.
- Actual GTA ped tasks using the project’s already-used `TASK_START_SCENARIO_IN_PLACE` native.
- Event-specific visual behavior driven by the XML event’s authored stages and ped roles:
  - reconnaissance, planning, vehicle preparation, and route observation use clipboard / planning behavior;
  - cargo, package, transfer, storage, and vehicle scenes use role-aware activity behavior;
  - lookouts, guards, and security use local guard-style behavior;
  - meetings and lower-risk gatherings use different idle/meeting scenario behavior.
- Nearby participants look toward other members rather than remaining as unassigned statue peds.
- Officer confrontation or actual gunfire escalates the scene into GTA flee/combat behavior.
- Backup only escalates the scene after officers have physically arrived and exited their own response vehicles.

I repaired this without deleting the Profile/loadout system:

- Pending ped, vehicle, and weapon streaming requests are **no longer immediately released** on the same attempt. The existing code was effectively requesting an asset and then calling `MarkAsNoLongerNeeded()` before a later tick could benefit from that request.

That explains the enormous amount of collision-guard activity around normal traffic. I changed it so the vehicle must actually be closing on the player, while the frame-level no-collision shield is restricted to an **immediate 3.25 m impact zone**. The scan interval is also relaxed from 350 ms to 500 ms and the temporary shield from 1,400 ms to 900 ms. Passing cars at 5–8 m should therefore stop being constantly interfered with.
